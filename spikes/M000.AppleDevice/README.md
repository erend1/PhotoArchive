# M000 Apple Device Capability Probe (spike-only)

Issue: [#3 — Apple device capability spike](https://github.com/erend1/PhotoArchive/issues/3) ·
Findings: [`docs/spikes/M000-APPLE-DEVICE-CAPABILITY.md`](../../docs/spikes/M000-APPLE-DEVICE-CAPABILITY.md)

This console probe measures what a Windows application can do with an iPhone using **only documented Windows APIs**:

| Path | API | What it talks to |
|---|---|---|
| Windows Portable Devices (WPD) | `IPortableDeviceManager`, `IPortableDevice`, `IPortableDeviceContent`, `IPortableDeviceProperties`, `IPortableDeviceResources`, `IPortableDeviceCapabilities` (PortableDeviceApi.dll) — declarations generated by [CsWin32](https://github.com/microsoft/CsWin32) from Microsoft's Win32 metadata | The iPhone's PTP camera interface (DCIM view) through Windows' in-box WPD MTP/PTP class driver |
| Windows.Media.Import | `PhotoImportManager`, `PhotoImportSource`, `PhotoImportSession`, `PhotoImportItem` (WinRT) | The same PTP transport, plus Windows' own sibling/sidecar grouping |

It is **not** production architecture and **not** a Photos-library API. It does **not** use, and the spike rejects:
libimobiledevice / usbmuxd / lockdownd / AFC (reverse-engineered Apple protocols), `MobileDevice`/`iTunesMobileDevice`
DLLs (private), parsing iTunes/Apple Devices backups (undocumented format), jailbreak tooling, or private iCloud endpoints.

## Safety

- Every command opens the device with `WPD_CLIENT_DESIRED_ACCESS = GENERIC_READ` (read-only), except the two
  explicitly guarded `*-experiment` commands.
- Output goes to `%LOCALAPPDATA%\PhotoArchive\M000-AppleDevice\runs\<timestamp>-<command>\`, **outside the repository**.
  Commands that write media bytes refuse to run inside a git working tree.
- `report.md` / `report.json` are **sanitized by default**: file-name digits are pseudonymized (relationships such as
  `IMG_#0001.HEIC` / `IMG_E#0001.HEIC` / `IMG_#0001.AAE` stay visible), dates are reduced to year-month, serials,
  UDID-bearing instance IDs and the user-assigned iPhone name are redacted, coordinates and identifiers are never printed.
- `raw/` (only with `--raw`, or as staging for `copy`) contains personal data. **Never commit or post it.**
- `copy` deletes its verified copies after hashing unless `--keep` is given.

## Prerequisites

| Item | Requirement | Notes |
|---|---|---|
| Windows | Windows 10 22H2 (build 19045) or Windows 11, x64 | Developed on Windows 11 25H2 build 26200.8246. ARM64 untested. |
| .NET | .NET 10 SDK | `winget install Microsoft.DotNet.SDK.10` |
| Apple software | **Apple Devices** from the Microsoft Store | Apple's documented prerequisite for importing to a PC ([support.apple.com/120267](https://support.apple.com/en-us/120267)). Record the version (`scripts/Collect-Environment.ps1` does this). |
| iPhone | Unlocked, trusted | Apple: unlock with passcode, then tap **Trust** on "Trust This Computer?" ([support.apple.com/109054](https://support.apple.com/en-us/109054)). Microsoft: "Your PC can't find the device if the device is locked." |
| Cable | Data-capable USB/USB-C cable | Charge-only cables are a common false negative ([support.apple.com/108643](https://support.apple.com/en-us/108643)). |
| Windows permissions | None expected | The probe is an unpackaged desktop app; no privacy prompt is expected. If Windows shows one, record it. |

### Settings that change the meaning of results — record them for every run

| Setting (iOS 18+ path) | Why it matters |
|---|---|
| Settings > Apps > Photos > **Transfer to Mac or PC**: Automatic / Keep Originals | Apple: USB import to a PC "might be converted to JPEG or H.264" unless **Keep Originals** is selected ([support.apple.com/116944](https://support.apple.com/en-us/116944)). Converted bytes are not the originals. |
| Settings > Camera > Formats: High Efficiency / Most Compatible | Determines whether originals are HEIC/HEVC or JPEG/H.264. |
| Settings > [name] > iCloud > Photos: **Sync this iPhone** on/off; **Optimize Storage** vs **Download and Keep Originals** | With Optimize Storage the phone keeps "space-saving versions"; Apple says originals must be downloaded to the phone before importing to a PC. |
| iCloud Shared Photo Library on/off; Hidden album in use | Unknown how these assets appear over PTP — record. |
| iPhone model, iOS version, Windows build, Apple Devices version, USB port/cable | Environment evidence. |

## Experiments (run in this order)

Every command prints the path of its sanitized `report.md`. Paste those files (or commit them under
`spikes/M000.AppleDevice/evidence/` — sanitized Markdown only) into Issue #3 together with the manual observations.

| # | Goal (capability rows) | Steps |
|---|---|---|
| E0 | Environment | `powershell -ExecutionPolicy Bypass -File spikes/M000.AppleDevice/scripts/Collect-Environment.ps1` (run once with the iPhone unplugged and once connected+trusted) and `& $probe env`. |
| E1 | Detection, trust, lock behaviour | `& $probe devices --watch 180`, then: plug in while **locked** → unlock → observe the Trust prompt → tap Trust → lock the phone for 30 s → unlock → unplug. Note the time each step happened. |
| E2 | Driver-declared capabilities | `& $probe inspect` — records supported WPD commands (does the driver offer delete / create-with-data?), `WPD_STORAGE_ACCESS_CAPABILITY`, events, firmware (iOS) version. |
| E3 | Read-only battery | `& $probe report` (all objects; add `--max 3000` on very large libraries). Enumeration timing, property presence, thumbnails, verified copies, Windows.Media.Import sources/items. |
| E4 | Original bytes vs. conversion | With **Keep Originals**: `& $probe copy --count 12`. Switch to **Automatic**, unplug/replug, run again. Compare "signature contradicts extension", "size match", and file types. Switch back to Keep Originals afterwards. |
| E5 | Identifier stability | `& $probe identity-snapshot` → unplug/replug → `identity-snapshot` → `& $probe identity-compare <first raw\identity-snapshot.json> <second ...>`. Repeat after restarting the iPhone, and after taking one new photo + deleting one old photo on the phone. |
| E6 | Live Photos, edits | Take a Live Photo; crop a photo; trim a video; then `& $probe copy --count 30`. Look for the "Live Photo candidate … share a UUID token" lines and `IMG_E*` / `.AAE` rows. |
| E7 | iCloud Photos + Optimize Storage | With iCloud Photos on and Optimize Storage on, compare the item count in Photos (Library > All Photos, bottom of the grid) with the image+video counts from E3. Open an old photo that shows a download indicator in Photos and check whether it appears in the enumeration and what `copy --object` returns. |
| E8 | Hidden / Recently Deleted / Shared Library | Hide a throwaway photo; delete another throwaway photo in Photos (it moves to Recently Deleted); re-run `enumerate` and check whether either is listed. If Shared Library is used, note whether shared items are listed. |
| E9 | In-session change events | `& $probe watch --seconds 120`: take a photo, delete a photo, lock, then unplug. |
| E10 | Disconnect mid-transfer | `& $probe copy --count 60 --max-total-mb 4000` and unplug during the run. Expected: errors recorded, `Partial staging files left behind = 0`, nothing promoted. |
| E11 | Windows.Media.Import import (optional) | `& $probe wmi-find --import 5` — imports 5 items into the run folder and reports which sibling/sidecar files Windows wrote. It never calls `DeleteImportedItemsFromSourceAsync`. |

### Guarded experiments (optional, destructive or write-attempting)

These exist so that delete/write-back conclusions rest on evidence. Use them only with throwaway items.

**E12 — delete one throwaway photo through WPD**

1. On the iPhone take a photo of a blank wall (and, separately, a Live Photo of a blank wall if you want to test pairs).
2. `& $probe delete-experiment --i-understand-this-deletes-from-my-iphone`
   - targets the **newest image** (or `--object <ID>` from a `--raw` enumeration),
   - prints the real file name/time locally so you can check it on the phone (Photos > item > ⓘ shows the file name),
   - makes and verifies a complete copy (size + SHA-256 + re-read) and keeps it in the run folder,
   - requires typing `DELETE <exact file name>`,
   - deletes **one** object without recursion, then reports whether the object and its same-number siblings
     (`.MOV`, `.AAE`, `IMG_E*`) are still listed.
3. Record manually: Is it in Photos > **Recently Deleted**? Did a Live Photo lose only one resource or the whole asset?
   With iCloud Photos on: is it gone from iCloud.com / other devices? Did the iPhone show any prompt?

**E13 — attempt to write one synthetic image**

`& $probe write-experiment --i-understand-this-may-add-a-test-image-to-my-iphone` (type `WRITE TEST`). Attempts to create a
64×64 grey JPEG under DCIM and the storage root through `CreateObjectWithPropertiesAndData`. Expected: refused. If it
succeeds, delete the grey image in Photos and report it.

## Command reference

Run `apple-device-probe help`. Common options: `--device N` (index from `devices`; default: the single Apple device),
`--out DIR`, `--raw`, `--no-sanitize` (local diagnostics only).

## Troubleshooting

- `No Apple device is visible through Windows Portable Devices` → unlock, trust, data cable, Apple Devices installed,
  "Apple iPhone" under *Portable Devices* in Device Manager. `scripts/Collect-Environment.ps1` shows which driver is bound.
- `0x8007001F … A device attached to the system is not functioning` during `copy` → record it (it is evidence), then
  retry with **Keep Originals** (widely reported to be linked to on-the-fly conversion; not an Apple-documented cause).
- `E_ACCESSDENIED` on open → phone locked or not trusted.
